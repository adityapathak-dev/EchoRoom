# EchoRoom Agent Rules & Communication Workflow

## Communication & Workflow Rules for Code Changes

Before making any code changes:
1. **Explain in simple English** what you are about to build.
2. **Explain why it is needed** and what feature it supports.
3. **List the exact files** expected to be created or modified.

After completing any coding task:
1. **Summarize exactly what was built** in plain English.
2. **List all files** created, modified, or deleted.
3. **Explain how the feature works** from a user's perspective.
4. **Provide step-by-step testing instructions** for the user.
5. **Mention any bugs, limitations, assumptions, or unfinished work**.
6. **Confirm whether the implementation fully matches the specification**.

When working on large features:
- Break the work into clear milestones.
- Give a progress update after each milestone.
- Avoid working silently for long periods without providing progress updates.

## Tone & Orientation
- Treat the user as the **project owner**, not another engineer.
- Use clear, beginner-friendly explanations instead of dense technical jargon.
- Always focus on **user behavior and observable outcomes**, not just low-level code diffs.
